# 虚拟滚动候选优化的对照与取舍

日期：2026-11-04。本轮使用当前工作区作为事实来源；对标本地 TanStack Virtual 3.19.10、virtua 0.54.1 和 vlist 3.3.4。用户授权逐项实验，以正确性和前后测量决定是否吸收，并要求 Git 可回退。

- `5186d54` 单独保存目录改名同步。

通过 `git revert <实验提交>` 可以撤销单项；实验以后的提交若依赖其 API，先逆序撤销依赖项。检查点保留原始工作，不用 hard reset、全树覆盖或改写远端历史回退。

## 测量约束

共享源码：[adoption workload](virtual-list-adoption-2026-11-04.rs)；工具：[compare-virtualization.py](../../tools/compare-virtualization.py)。比较前后各构建一个 Release 二进制，再按 before/0 → after/0 → after/1 → before/1 串行采样。采样前等待 cargo/rustc 退出；不切换生产工作区到旧版本。基线源码放在提交哈希独立目录，避免另一轮残留文件参与编译。

记录每样本时间、分配次数、临时堆峰值、source 访问和内容准备次数。分配统计只覆盖当前线程；不是进程 RSS、GPU 显存、物理帧率或真实窗口的 CPU。初次 A/A 对照使用相同生产源码，不将正常波动视为优化。原始数据见 [A/A CSV](virtual-list-series-adoption-baseline-2026-11-04.csv)。

实验源码哈希、基线提交和特性开关由工具保存在本机逐次日志的 identity.json。新接口实验仅在 after 显式启用对应特性，before 使用相同业务准备逻辑；这种比较会明确标记为可选 API 收益。

## 候选与决策规则

1. Masonry 的有界内容准备复用及重复工作集读取。比较稳定范围、远距离往返和普通 renderer；检查内容／布局失效、替换、焦点、卸载释放。
2. 宽度变化失效。先比较稀疏已测状态的持久路径修改，不预设引入全局代次；保留稠密状态的线性路径。检查旧宽度不能成为真实测量、锚点和冻结快照。
3. 测量缓存导出。按树摘要跳过未测子树，保留稠密线性遍历；比较空、百万项稀疏与稠密缓存，验证顺序和约束。
4. Masonry 持旧快照追加。比较索引分块持久化的复制成本和稳定查询代价；只有总体收益足以抵消索引开销才采用。
5. Measured 元数据压缩。先试验稀疏焦点信息的紧凑表示，比较构造、稳定帧、resize 和真实焦点；不新增第二份测量真值。
6. 方向缓冲与估算。保持消费者策略和核心几何分层；比较相同输入轨迹的构建、空白和换向，不能仅凭减少节点修改默认值。

普通回归必须通过，冻结快照、唯一滚动 owner、原子失败和资源释放合同不得降级。某一场景提速不足以掩盖其他必要场景的明显退化。拒绝或缩小的实验保留测量和理由，生产实现恢复到该项基线。

## 测量缓存导出：吸收

基线 `b729887`。原 API 返回值不变，依据原生树的 measured 摘要跳过整棵未测子树；已测超过四分之一时使用原有线性路径。按真实已测数量一次分配结果容量，不增加测量镜像、逐项 key 索引或新的公开 API。

每样本执行 100 次导出，ABBA 每版本 10 样本；中位数如下。[原始 CSV](virtual-list-series-adoption-cache-2026-11-04.csv)。

| 逻辑数量／已测数量 | 改前 ms | 改后 ms | 改前／改后分配次数 | 改前／改后临时峰值 B |
| --- | --- | --- | --- | --- |
| 1,000／0 | 0.22845 | 0.00100 | 0／0 | 0／0 |
| 1,000,000／64 | 486.225 | 0.28630 | 500／100 | 1,024／1,024 |
| 10,000／10,000 | 4.06335 | 3.46090 | 1,300／100 | 262,144／160,000 |

这是冷导出的整批 CPU 成本，不是每帧时间。收益来自跳过未测数据和减少结果 Vec 扩容；稠密路径没有明显退化。新增语义测试覆盖乱序反馈后的有序导出、hint 排除、局部失效和冻结快照；完整专项 101 passed / 8 ignored。此项采用。

## Masonry 内容准备缓存：作为可选 API 吸收

基线 `49f0a81`。增加 `VirtualMasonry::new_with_item_views`，与一维列表保持相同语义：缓存工作集中的 `AnyView`，每帧仍产生新的 Element，执行正常渲染和布局。默认 `new` 继续逐帧调用 renderer。缓存 stamp 包括领域 key、source 内容版本、显式外部内容版本、本地内容 epoch 和 index；纯几何变化不重新执行内容工厂。局部失效、结构替换和 owner 交换均有独立处理。

[准备实验 CSV](virtual-list-series-adoption-preparation-2026-11-04.csv)，每样本 120 帧，100,000 项，每项准备 256 个格式化字符串。before 使用普通 renderer，after 显式选择新 API；两者业务准备和 View 渲染一致，不把该收益归因于普通构造器。

| 轨迹 | 改前 ms | 改后 ms | 分配次数 前→后 | 工厂调用 前→后 |
| --- | --- | --- | --- | --- |
| 稳定工作集 | 26.72065 | 7.81310 | 403,080→29,160 | 1,440→0 |
| 远距离交替 | 27.35660 | 27.81405 | 410,404→409,806 | 1,440→1,440 |

稳定工作集耗时降低约 70.8%，分配降低约 92.8%；快速交替不能复用，耗时增加约 1.7%，工作集外的 View 及时释放。采用 opt-in 接口，不强制廉价行付出缓存成本。[普通 renderer 对照](virtual-list-series-adoption-preparation-ordinary-2026-11-04.csv)覆盖四后端 17 种稳定／跳跃／复杂内容／resize 轨迹；分配次数完全一致，Masonry 中位数变化 −2.3% 至 +4.2%，处于 A/A 波动范围，未见稳定的额外分配或全量扫描。

新增回归覆盖三种 sizing 的稳定复用、宽度只重测不重建内容、局部与 source/external 版本失效、非法批次、追加前缀、结构替换屏障、远端 retained 行、同 ID 换 owner、切回普通 renderer 和卸载释放。专项新增 2 项通过，原有 101 项也通过；完整检查在本轮结束统一执行。元数据 scratch 复用未与此项混合，避免把不同来源的收益合算。

## 原生 Measured 宽度失效：吸收

基线 `47f0a2e`。[resize CSV](virtual-list-series-adoption-resize-2026-11-04.csv)。复用同一原生树，在摘要现有 padding 中增加 `has_measured_items`，包括 valid=false 的 Measured 变体；宽度变化只将这些叶子转为 hint，并共享未变化子树。需要填充默认 hint 的 unknown 叶子也包含在候选中，超过四分之一时回退原有线性重建。摘要不增加大小、不增加一份尺寸缓存，保留 measuring reset、geometry revision 和锚点调整。

| 工作负载 | 改前 ms | 改后 ms | 分配次数 前→后 | 临时堆峰值 B 前→后 |
| --- | --- | --- | --- | --- |
| 稀疏 1,000 项，40 次 resize | 2.68915 | 1.92585 | 9,002→6,042 | 104,120→17,080 |
| 稀疏 100,000 项，40 次 resize | 118.21245 | 2.09290 | 370,082→6,762 | 9,451,864→23,224 |
| 稀疏 1,000,000 项，40 次 resize | 1,341.45300 | 2.22355 | 3,643,442→7,122 | 94,210,392→26,296 |
| 稠密 10,000 项，一次 resize | 0.42150 | 0.36310 | 989→989 | 950,920→950,920 |
| 稠密 100,000 项，一次 resize | 3.70245 | 3.25610 | 9,184→9,184 | 9,450,816→9,450,816 |

稠密场景保留完全相同的分配和重建路径，时间波动不作为该路径算法提速的证据。原生新增测试验证稀疏／稠密旧宽度尺寸降为 hint，新的真实测量全部属于新宽度，冻结快照不变；专项 103 passed / 8 ignored，原生集成 10 passed。此优化仅针对原生 Measured 树，不把 Masonry 的 KnownGeometry 失效成本算入收益。

## Measured 焦点元数据压缩：拒绝此版本

基线 `b7fe55f`。试验将 ListItem 中的 `Option<FocusHandle>` 改为私有 `Option<Rc<FocusHandle>>`，共享冻结树中少数焦点资源。完整专项 103 passed / 8 ignored；新增原生资源寿命测试通过，11 项集成全部通过。正确性成立，但不能只看无焦点场景。

[常规测量 CSV](virtual-list-series-adoption-metadata-2026-11-04.csv)中，百万项 retained heap payload 从 93,095,288 B 降到 66,912,344 B（−28.1%），构造 21.75365→15.42845ms，分配数保持 90,952。`memory-*` 和 `focus-memory-*` 行的 `builds` 列特指 retained payload B；不是内容准备次数，且不是 RSS。

[焦点密度 CSV](virtual-list-series-adoption-focus-metadata-2026-11-04.csv)固定 10,000 项、焦点句柄本体预先构建，统计列表持有它们的增量成本：

| 有焦点项 | 构造 ms 前→后 | 常驻 B 前→后 | 分配次数 前→后 |
| --- | --- | --- | --- |
| 64 | 0.20440→0.13665 | 933,096→673,800 | 935→999 |
| 10,000 | 0.43680→0.50000 | 933,096→1,150,728 | 935→10,935 |

每行可聚焦的列表是必须支持的原生用法，出现约 23.3% 常驻增长、14.5% 构造退化和 10,000 次额外分配。[逐帧对照](virtual-list-series-adoption-metadata-frames-2026-11-04.csv)无法消除这一代价。因此拒绝 Rc 方案，单独保存试验实现后 Git revert，仅保留 workload、焦点寿命测试和证据。后续若再试，应使用不为每个 focus 分配堆对象的紧凑布局，并重跑相同密度矩阵。
