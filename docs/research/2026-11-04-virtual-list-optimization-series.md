初始生产基线为 e768cd7；已有 ImagePreview 测试修正单独保存为 97f79ac。浏览器快照、日志、target、TEMP、refer 与 Python 字节码不提交。研究目录中的源码、失败证据和 CSV 是可审计的项目资料，保留提交。

## 0. 可重复的基准

- [同一份 workload](virtual-list-optimization-series-2026-11-04.rs)运行在提交快照与当前生产源码上；[比较脚本](../../tools/compare-virtualization.py)从 Git archive 生成隔离源码，不切换、覆盖或回滚工作区。
- 先完成两个 Release 构建，再按 before → after → after → before 采样。相同生产源码的初始对照见[基线 CSV](virtual-list-series-baseline-2026-11-04.csv)，共 156 行；这只校验测量流程，不宣称优化收益。
- Fixed／Known 十万项，Measured Masonry 一万项；正常与复杂条目、快速远距往返、跨轴 resize、动态尺寸变化。动态尺寸变化仅用于 Masonry，Fixed/Known 不以偷偷改变已知尺寸制造错误输入。
- 每案例每轮 3 样本；每样本 20 帧预热、120 帧采样，记录帧 P50/P95/P99、总时间、主线程分配数／临时峰值、source 调用数和构建数。另设工作集迭代、无变化尺寸反馈、保留快照追加的纯 API 探针。
- 分配统计为 thread-local；后台线程分配不计入。CPU 为 headless 输入／布局／提交，不能替代实窗 CPU、GPU 或物理 FPS。不同轨迹的实际工作集可能不同，比较只在相同案例和相同构建／读取工作量下进行。

初始样本中，一维简单稳定帧 P50 约 31–32µs，复杂条目约 251–252µs；Masonry 简单稳定帧约 82µs、resize 约 96µs。它说明条目内容与动态布局需要独立计量，不把范围算法当作整个组件成本。数值不是产品性能承诺。

复现：`python tools/compare-virtualization.py --before <commit> --label <name> --filter <test>`。默认构建缓存位于 C 盘，避免 D 盘空间不足。对比脚本会保存逐次输出与身份记录，CSV 保存在本研究目录。采用条件为语义回归通过，并有稳定可解释的时间／分配／正确性收益；毫秒级微小抖动不单独构成采用理由。

## 1. 连续工作集：采用

基线 762efe9。无额外保留项时直接从已验证的连续 range 读取几何，不创建、排序或预遍历索引 Vec；显式 working_indices 仍返回 Vec，稀疏保留项仍遵守有序并集，不遍历中间远距条目。

[前后 CSV](virtual-list-series-workset-2026-11-04.csv)：每样本 10,000 次迭代、30 个普通项，Fixed 分配 10,000→0，时间中位数 4.256→3.613ms（约 −15.1%）；Known 分配 10,000→0，4.847→4.125ms（约 −14.9%）。每组均保持 600,000 次 source 调用。带远距 retained 的路径保持原分配／读取工作量，不把小幅时间抖动当作新增收益。

新增两轴、Fixed/Known、连续／稀疏、首中尾窗口的语义回归；virtual_list 全专项和 Select 回归验证后提交。采用理由是消除了可确定的每次索引分配，同时保持公共顺序、身份和几何合同。比较脚本还会等编译器退出再开始采样。

## 2. Masonry 最终帧元数据：采用

基线 32998c5。[前后 CSV](virtual-list-series-masonry-frame-2026-11-04.csv)保持相同的构建根数。在最终几何确定后，只准备一次条目元数据，供补充布局、prepaint 和阅读锚点提交消费；实际几何修改仍重新求工作集，不跨帧保存 AnyElement。

120 个稳定帧的 source 读取 22,680→16,200（−28.6%），分配 33,903→32,703；总时间中位数 10.377→9.674ms（约 −6.8%）。快速远距往返读取 20,160→14,400，总时间 9.722→9.017ms（约 −7.3%）；resize 和动态尺寸变化也减少读取／分配，构建数分别保持 3,240／2,718。复杂内容占主导时耗时差异很小，不扩大收益声明。

新增生产帧计数回归，九个稳定根每帧 source 查询从原本七次/根降至五次/根；virtual_list 93 passed / 8 ignored，覆盖原有预算、焦点、用户接管、可见覆盖及生命周期。采用依据为确定的重复查询／分配消除，并有稳定与快滚轨迹收益。

## 3. 无变化测量反馈：采用

基线 1525749。[前后 CSV](virtual-list-series-masonry-noop-2026-11-04.csv)包括所有纯 API 与帧轨迹。帧内仍真实布局内容，但仅在尺寸改变或首次转为 measured 时提交反馈；公共 update_sizes 仍校验完整批次，按索引排序验证重复项，再过滤无变化记录。空变化直接返回，不创建分列更新，不修改 revision。

10,000 次、每批 30 项的稳定反馈，分配 100,000→10,000，耗时中位数 15.162→5.290ms（约 −65%），source 查询均 300,000。120 个生产稳定帧读取 16,200→12,960、分配 32,703→28,983；快速往返 9.728→8.806ms，构建均 2,880。稳定／resize／尺寸变化的时间中位数分别略增约 0.8%／1.4%／0.5%，不声称这些轨迹都提速；采用依据是确定的反馈事务、分配和重复查询消除，并保留公开输入校验。

无变化重复 key 仍失败；有效改变后跟随非法项不发生部分写入。首次 measured、cross 变化、内容失效不能被过滤。新增原子性回归，稳定帧源查询降为四次/根；virtual_list 94 passed / 8 ignored，原有动态估算、预算、呈现与输入回归全部通过。

## 4. 滚动结束计时：采用

基线 f84e55a。[前后 CSV](virtual-list-series-idle-2026-11-04.csv)使用同一组 2,000 次、间隔 100µs 的活动及结束/重启断言，ABBA 共十个样本/版本。会话内只保留一个任务；输入更新最后活动时间，任务醒来检查剩余等待时间，不再逐次取消和重建任务。卸载和解绑仍取消任务，binding/session 校验隔离旧任务。

耗时中位数 6.1705→0.68465ms（约 −88.9%），主线程分配 40,419→4,025（约 −90.0%），临时峰值 116,432→876 字节。此为测试执行器中的调度工作量，不是实窗 CPU/GPU 或物理帧率。两个版本都验证持续输入不提前结束、停止 120ms 恰好一次 ScrollEnd、后续会话可重新启动。

新增长于初始截止时间的连续活动回归；virtual_list 95 passed / 8 ignored。保留纯 owner 的 poll_scroll_idle 接口，不添加帧轮询、额外输入处理或逐项状态。
