# 26 局部背景高斯模糊基础层

日期：2026-11-02。当前目标平台：Windows D3D11。此能力属于 GPUI 绘制层，供任意 Styled 容器复用，不属于 ImagePreview 的私有实现。

## 1. 接口与职责

```rust
div().backdrop_blur(rems(1.0)).rounded_md().bg(tint)
```

`backdrop_blur` 参数是高斯标准差 sigma，使用 AbsoluteLength；随 rem 和显示缩放换算为物理像素。零禁用，负值及非有限值忽略；逻辑 sigma 上限 64px。基础层只负责采样当前窗口中已绘制的内容、可分离高斯滤波、圆角及内容裁切和元素透明度。颜色、描边、阴影、尺寸和图标属于消费者及其 token。元素自身的文字、按钮、背景色及描边在模糊之后绘制，保持清晰。

不是窗口背景材质，也不是对源图片预处理。图片、棋盘格、文字和先前覆盖层都属于可采样背景。每个模糊是绘制顺序屏障，不能被普通几何批处理移到背景之前或内容之后；嵌套和重叠区域按绘制顺序依次采样。PaintSnapshot 记录滤镜命令，回放时平移及裁切，不冻结背景像素。

## 2. GPU 管线与性能合同

1. 输出区域先与 content mask、窗口边界相交；不可见区域、零强度或零透明度直接跳过。
2. 只拷贝输出区域向外扩展 `ceil(3 sigma)` 的 ROI，扩边裁到窗口范围；不为小工具条复制整个窗口。
3. 水平和垂直两遍归一化 Gaussian，核截断于3 sigma并重新归一化。在较大物理 sigma 时先做四点双线性预滤波降采样，将工作 sigma 限制在8像素；在工作纹理的相邻texel上配对采样，每轴最多25次采样。两张中间纹理使用RGBA16F，避免反复量化。高分辨率BGRA8原始ROI保留用于准确合成。
4. 圆角边缘和父透明度决定原始值与模糊值的插值；合成采用替换写入，避免把背景 alpha 叠加两次。子元素正常绘制。

资源由窗口 renderer 持有并惰性创建；没有模糊的场景沿用原绘制路径。所有玻璃区域串行复用一套中间纹理，容量分桶增长以避免拖动或尺寸细变时反复分配。连续窗口resize保留仍可用的局部容量；只有旧容量超过缩小后视口的分桶上界才释放，设备丢失和窗口renderer销毁释放全部资源。滤波权重可复用，不进行 CPU 背景截图或读回。绘制命令不自行请求下一帧，不引入常驻定时器；背景变化由现有窗口失效机制驱动。

容量按64像素分桶，每窗口保留纹理总额上限64MiB（捕获纹理4字节/像素，两张工作纹理合计16字节/像素）。历史宽高组合超预算时先按本次需要收缩容量；本次仍超预算则只跳过该区域滤镜，保留正常底色、警告一次，并继续服务其他小区域。纹理增长过程可能短暂同时持有新旧两组，64MiB是保留容量上限，不是进程或瞬时显存硬上限。

可复现预算示例：4K窗口中240×40逻辑像素、sigma16、100%DPI的表面，扩边ROI为336×136（45,696像素，整窗的0.551%）；工作纹理168×68。分桶容量384×192及192×128，合计688,128字节（约0.66MiB）。同尺寸表面的Gaussian工作面积在100%～400%DPI下近似不变；原始ROI拷贝与最终合成仍随物理面积增长，不能宣称DPI没有成本。

启用 `gpui_windows::directx_renderer` 的trace日志可查看每帧实际处理区域数、拷贝像素、滤波及预滤波像素、纹理创建次数、保留容量峰值、核重建次数及超预算跳过数。计数不触发额外帧；窗口没有重绘请求时不运行滤镜。如果窗口因其他动效重绘，滤镜仍按帧采样，首版不缓存背景像素；仅复用纹理和最多8个滤波核，避免背景更新后显示旧结果。首次使用需要创建shader与纹理，Debug还会运行时编译shader；Release携带预编译字节。

性能范围：成本取决于可见 ROI 面积、DPI 和玻璃区域数；重叠玻璃需要独立采样，不能错误共享背景结果。整窗或密集列表玻璃不是免费效果，消费者应缩小使用面积。自动测试记录区域大小、工作像素与资源复用；真实硬件耗时须通过 GPU 时间测量，不把 WARP 软件渲染速度当成用户硬件帧率。

## 3. 平台与故障边界

第一版真实滤镜仅由受维护的 Windows D3D11 补丁实现。Scene 保留透明 Quad 标记及滤镜元数据，其他 renderer 不增加穷尽分支，只显示消费者配置的普通 tint。初始化或分配失败时保留 tint，记录错误并在本次设备生命周期内停止重复尝试；设备重建后可恢复。主题表面必须在降级时仍可读。

补丁位置：`vendor/gpui-pre`（Style、Styled、Window、Scene）、`vendor/gpui-pre-windows`（D3D11 和 HLSL）。根 Cargo patch 与 Cargo.lock 必须一起携带，外部宿主须自行声明 patch。

## 5. 先测量，再优化

像素数、采样次数和资源预算用于解释成本，不代替耗时测量。当前提供两种互补诊断：

- **计数**：现有trace记录regions、copied_pixels、work_pixels、texture_allocations、kernel_rebuilds、peak_scratch_bytes和skipped_regions，判断面积、区域数量及分配是否失控。
- **阶段耗时**：`backdrop_profile.rs` 使用D3D11 GPU timestamp，分别测copy、downsample、horizontal、vertical和composite；CPU记录参数／资源准备及各阶段命令提交，不能把CPU提交耗时当GPU执行耗时。

诊断默认关闭，不创建GPU query、不读取CPU时钟。需要宿主日志系统允许 `gpui_windows::directx_renderer` 的info日志，再在**启动进程前**设置：

```powershell
$env:GPUI_BACKDROP_PROFILE = '1' # 每个有效区域采样；诊断开销较大
# 由用户自行启动宿主并执行待测交互
Remove-Item Env:GPUI_BACKDROP_PROFILE
```

数值N表示每N个有效区域采一个；0、未设置或无效值关闭。稀疏采样可能与固定区域顺序产生偏置，定位阶段先用1；如用61降低开销，仍须核对各个区域都被覆盖。不要在最终性能基线中一直开启细粒度诊断。

所有同帧区域共用一次timestamp-disjoint区间，遵循D3D11每帧至多一次的约束。最多8个在途帧、128个区域样本，query预建并复用；环满跳过样本，不扩容、不等待。读取保留原始HRESULT，`S_FALSE`表示尚未就绪，不能当有效时间；生产路径只用DONOTFLUSH非阻塞读取，不主动Flush、不增加定时器和重绘请求。只有后续正常绘制才收取已完成样本，最后一帧可能没有日志。初始化诊断失败只关闭诊断，不关闭模糊。

### 5.1 离屏硬件基准

```powershell
pwsh -NoProfile -File tools/test-gpui-backdrop.ps1 -Profile
```

`-Profile`自动选择Release，运行显式启用的硬件基准；常规正确性测试不自动跑性能基准。使用真实硬件D3D11 device，打印adapter信息；硬件不可用时失败，不用WARP替代性能数字。不创建HWND、swapchain或Showcase窗口。

每个场景使用新device和3840×2160离屏目标，上传一次背景；每帧开始在GPU恢复同一背景，避免反复滤波逐渐改变测试负载，恢复命令放在计时区间之前。首次调用1帧、预热32帧、稳定测量128帧。之后关闭组件分阶段profiler，再预热32帧、测128帧，仅保留整组区域外的一对GPU timestamp（`envelope`），对照诊断扰动。脚本关闭继承的实时诊断环境设置，由基准自行控制采样。每帧结果等待仅发生在基准中，排除于CPU提交计时之外；不读取背景像素。无效disjoint样本丢弃，有效稳定样本须至少100帧。稳定期纹理创建和核重建必须都是0。

结果字段：`PROFILE_ROW`给出CPU及GPU的P50／P95，单位µs；`PROFILE_CPU`和`PROFILE_GPU`给出分阶段**算术均值**。`envelope`不提供阶段细分。多区域GPU阶段之和用于定位各滤镜内部成本；envelope覆盖整组区域及其间的状态恢复／命令间隙，二者计时边界不同。

这些是GPU命令流时间区间，可能包含流水线等待、资源依赖或供给间隙，不是GPU busy占用率。基准每帧排空队列，无法再现真实窗口的多帧流水；也不含组件布局、图片解码、完整Scene上传／绘制、Present、DWM合成和输入延迟，不能据此声称整个应用的帧率或所有硬件表现。

## 8. 首轮优化与保留依据（2026-11-02）

### 8.1 实际采用的改动

仅对工作纹理面积至少16,384 texel、且确实能缩小中间绘制矩形的区域启用裁剪。此阈值是本轮的保守启用策略，不承诺所有形状或硬件都有同样收益；小工具条和握把继续使用原shader路径。

- 保留原始ROI、3σ扩边、工作分辨率、sigma、采样权重、两遍高斯顺序与RGBA16F精度。没有降低模糊质量档位，也没有缓存背景结果。
- 在工作网格上计算最终双线性重建需要的矩形，再保留**两圈texel保护边**。水平高斯只绘制所需列，仍覆盖完整高度以提供垂直卷积halo；垂直高斯只绘制最终重建需要的矩形。纹理容量和64MiB保留预算不变。
- 裁剪shader使用物理像素中心 `SV_Position` 作为工作纹理坐标，避免把裁剪矩形重新映射成整张纹理。小表面的原shader仍以原UV路径执行，裁剪shader仅在首次实际需要时创建。
- 两张半浮点纹理每次新分配后仅初始化清零一次，避免未初始化padding中的NaN污染双线性读取。此项增加首用工作，不是每帧清屏；`initialization_clears`计数可验证稳定帧为0。两圈保护边隔离局部未绘制texel及浮点插值边界，不能擅自缩成一圈。
- `work_pixels`改为记录实际绘制面积之和，不再把未绘制的完整中间纹理也计入。大面板由870,912降至804,912 texel／帧，减少**7.58%**；这不是显存减少比例。

### 8.2 对照方法与实测收益

`-Profile`现增加 `optimized`／`reference` 两组：同一个device、背景、核、纹理池和计时器，关闭分阶段诊断，按AB／BA交替执行，预热32对、每组测128帧。reference强制原始完整中间pass及原UV shader；两组均使用新增的一次性纹理初始化，稳定计时不含该初始化。各自有效帧至少100，稳定期纹理创建、核重建和初始化清零都须为0。

RTX 4070 Ti SUPER、Release、4K离屏，连续3轮结果如下。范围是每轮分位数的最小～最大值，不是置信区间；百分比按**同轮**两组数据计算。

| 场景／指标 | 原完整pass reference | 优化路径 | 判断 |
| --- | --- | --- | --- |
| 1200×800、sigma16：GPU P50 | 44.160–44.256µs | 41.696–41.760µs | 每轮降低5.43%／5.78%／5.64% |
| 同面板：GPU P95 | 44.672–44.800µs | 42.208–42.304µs | 三轮均下降 |
| 同面板：CPU P50 | 15.9–16.0µs | 15.9–16.1µs | 没有可确认CPU收益 |
| 工具条＋握把100%：GPU P50 | 22.272–23.200µs | 22.368–23.264µs | 原小表面路径；无可确认收益 |
| 工具条＋握把200%：GPU P50 | 24.000–24.960µs | 24.032–25.024µs | 原小表面路径；无可确认收益 |
| 16个工具条：GPU P50 | 192.608–200.544µs | 192.576–200.544µs | 同轮差异不超过0.05%，无可确认收益 |

本轮保留的是大面积表面的稳定GPU收益，不能声称当前ImagePreview两处小玻璃或整个应用快了5.6%。没有减少绘制区域数量、合并跨屏障背景采样，也没有改变多层玻璃的读取顺序。完整记录见 [三轮优化对照](performance/2026-11-02-backdrop-optimization.log)。第5节列出的离屏、排空队列及整帧测量限制仍适用。

### 8.3 未采用的方案

全尺寸统一裁剪在工具条／握把上未见收益，故不对小表面启用。固定上限循环展开的独立Gaussian shader在16工具条对照中约214.2µs，而原路径约196.0µs，反而变慢，已撤回。直接采样framebuffer配合混合合成的实验在透明边缘未满足原像素合同，也已撤回；最终代码没有该路径，不修改swapchain采样能力和原替换合成方式。上述实验记录位于本地`target/backdrop-optimization-*.log`，不作为保留方案的成绩。
