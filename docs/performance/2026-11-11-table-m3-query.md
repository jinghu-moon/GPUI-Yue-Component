# YueTable M3 TB04 查询管线基线

日期：2026-11-11。这是新增查询功能的 release 基线，未与旧实现配对，不作优化收益结论。功能与 API 见 [M3](../45-table-m3.md)。

## 验收

三轮独立进程、每轮 11 条件×6 次执行，共 198 个有效样本。每条件第一次执行与后五次重复执行在原始 CSV 分开；没有刷新 CPU／操作系统缓存，所以不把“第一次”称为硬件冷缓存。每次完整 key 顺序、总数与页范围均先按独立 oracle 断言；计时只包生产查询或最终 commit，不含 fixture、oracle 构造或 key 对比。另有 Table 29 项、Showcase 表格 4 项、VirtualList 193 项回归，严格 Clippy 和独立消费者编译通过。

第二轮第一次尝试在运行中观察到编译／Showcase 干扰，整轮弃用并保留日志。接受三轮都完整通过，没有混用弃用轮的样本；采样开始／结束及归档前确认源码和可执行文件身份一致。过滤、稳定排序、分页／投影和最终接受走实际代码。零查询重算预算由真实表格滚动、选择、rem 与主题更新的谓词计数测试通过。

## 数据与计时

Windows 11 26100，Intel i5-13600KF，release opt-level=3，debug assertions=false。250,000 条×8 业务字段：稳定 key、中文名称、重复金额、bool、可缺失值、日期、嵌套 priority 和分类；默认金额降序、bool 升序，同值保留输入顺序。包含宽／窄／零匹配、组合、清除与第二页。

查询计时含规则验证、扫描／过滤、稳定排序、分页及 key 反查索引；最终接受包含完整候选验证、发布及旧视图释放，不含 Window::draw、GPU、原生呈现或输入延迟。没有将 CPU 查询时间换算为 FPS。所有 250k 原始 Row 由一个 source 共享，不克隆业务记录。生产路径没有因为统计而增加全表查询，分段诊断入口仅在 headless-tests feature 下公开。

## 复现

先构建 `cargo test -p yue-component --release --features headless-tests --test table --no-run --message-format=json`，取构建记录中的 table executable，再运行：

```powershell
python tools/sample-table-query.py --executable <table-test.exe> --build-record <build.jsonl> --output target/table-query-new
```

输出目录必须不存在。runner 自带安静门禁、运行中进程干扰检查、完整样本检查和源码／可执行文件 SHA-256。只运行预构建文件，采样期间不编译。原始目录 `target/table-m3-evidence-01`，归档内包含完整 CSV、三轮接受日志与弃用日志、构建／源码身份、实际改动源码、功能检查和可独立运行的 verification-script.py。

[证据归档](evidence/2026-11-11-table-m3-query.zip) 的 SHA-256 记录在阶段实施进度。GPU、真实 IME、Narrator 和跨屏 DPI 仍未由本次 headless 采样证明。
