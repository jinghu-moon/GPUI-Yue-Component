# YueTable 固定 workload 与性能门禁方案

日期：2026-11-10；对应 [Table 主设计第 21 节](../45-table.md#21-性能合同与验证方案)。本文是完整采样协议；M1 已增加 TB01 headless 工作集对照、CPU 探针和最小 runner，实际证据与进程门禁状态见 [M1 实施记录](../research/2026-11-10-table-m1-implementation.md)。M2布局、M3 TB04、M4 TB03／TB06、M5 TB02与M6 TB05均已增加headless基线（见各阶段报告）；完整native／GPU／输入延迟仍未验收，不将参考库数字换算成 GPUI 分数。

## 1. 比较对象与不变量

每个候选只比较一个明确变更；记录 baseline commit、candidate commit／工作区 diff、源码和 workload 哈希、lock／features／二进制身份。两版本使用相同数据、列定义、操作轨迹、随机种子、构建类型、窗口和缩放；修改 workload 后双方重跑，不能把不同版本日志合并。

优先复用 [compare-virtualization.py](../../tools/compare-virtualization.py)、[既有证据解析](../../tools/virtualization_evidence.py)和[门禁合同清单](../../tools/virtualization-contracts.json)的构建隔离、进程干扰检测和身份记录。原脚本继续服务虚拟化实验。新增的 [sample-table.py](../../tools/sample-table.py)复用既有严格测试输出核验，并沿用先构建后采样、ABBA、进程干扰和身份门禁；提供 TB01／布局／TB02／TB03／TB06 的 headless CPU 与工作集基线，TB04查询和TB05快照替换分别使用独立runner，不假定现有 FRAME CSV 已包含 GPU、输入延迟或原生呈现 p99。

所有 fixture 是确定生成，不读取网络；数据准备和朴素结果 oracle 在查询计时外。初次 source 建索引、冷缓存、首次挂载和持续滚动分别报告，不能预先建立缓存却称作冷启动。性能优化前先通过同一行为正确性验收。

## 2. 标准 fixture

统一基准宿主内容区为 64rem×32rem，正文最大高度 28rem，基准 rem 为 16px；另以 12／24px 的 rem 基值运行布局正确性，不能将不同 rem 数据互比。Medium、固定主题 light／neutral 作为性能基准，四主题／三密度另作正确性矩阵。表头、summary、footer 实际占用计入几何，正文不是强制 28rem。

| ID | 数据与模式 | 固定内容／操作 | 阶段与目的 |
| --- | --- | --- | --- |
| TB01 | 100,000 行×12 叶列，Rows＋Fixed；对照 1,000 行×同列 | 8 文本、2 数值、1 状态、1展示列；seed=45，key 为业务编号；无图片和持续动画 | M1；稳定滚动构建／分配与总行数解耦，正文之外计入表头／冻结／保留项 |
| TB02 | 50,000 行×256 列，Cells＋Known | 行高按 key 在合法的 3 档已知高度循环，列宽 3 档；Start／End 各 2 列、首／尾各 1 行；第二轮 16 个合法 span | M2／M5；两轴有界、冻结交叉、屏外 origin、稀疏 active；不先分配全部 12,800,000 cell 对象 |
| TB03 | 20,000 行×8 列，Rows＋Measured | 文字按 key 分为 1／2／4 行，Avatar、状态和真实 Button；固定本地资源集 512 张 64×64 图像，冷／热分开 | M4；行高反馈、锚点、复杂 cell 与图片字节预算；普通文字表不为它建立图片服务 |
| TB04 | 250,000 条×8 业务字段，本地查询规则探针 | 中文名称、重复排序值、0、false、缺失、日期与嵌套业务取值；宽／窄／零匹配、组合筛选、清除条件、分页 | M3；完整 key 顺序／total／页范围先等价，再区分过滤、排序、投影和最终接受耗时 |
| TB05 | 10,000 行×16 列，Rows＋Fixed／Measured 两个独立变体 | 同快照修改 1 个屏内格、1 个屏外格、64 个格；另改排序字段／长文本；反复替换 source 100 次 | M1／M4；局部失效与正确依赖、旧 snapshot／任务释放，不能只看 factory 次数 |
| TB06 | 50,000 树节点，500 根，每根 99 子节点，Rows | 初始展开前 10 根，显示数据行为 1,490；根分页、折叠／恢复、节点加载失败与重试；业务 key 固定 | M4；结构域／显示投影／工作集分开计数，不把整树构建隐藏在滚动基准外 |

不存在的阶段标为 NotImplemented，不能用 Static 或简化 renderer 替换后记为通过。TB02 的 End／尾冻结在 M2 扩展前明确阻塞该变体；无冻结变体可先测，但不能冒充同一 workload。所有插入数据、样本文本和资源摘要在实施时固化到 fixture，生成器变化需推进 workload version。

M1 的首份 headless 探针是 **TB01 的简化文本变体**：12 个文本列，逐帧偏移为 `-((frame * 37) % 8000)`。它验证规模变化下的工作集与 CPU draw 基线，不覆盖上表 8 文本／2 数值／1 状态／1 展示的完整列形状。runner 身份中的 `W2 repeated vertical trace` 为早期标签；实际是重复纵向轨迹，不能当作下表 W2 的 200 组首／中／尾跳转及活动格回窗验收。后续补完整 fixture 时推进版本、双方重采。

TB03 的图片数量与尺寸是测试输入，非缓存容量默认值；实际使用者、热缓存和纹理字节分别报告。TB06 显示行数不含 header／summary；测试另校验语义总量，不能把数据行数直接写入全部语义坐标。

M6新增的TB05是完整快照替换变体：每次同时更新row0、row9000和rows128..191，数值变化并交替短／长换行文字；Fixed／Measured各三独立进程、每进程100次。分开计准备、接受、draw＋effects，直接检查可见新值、所有旧source释放及空闲零构建。它不提供逐cell damage或排序字段变更收益证明；typed查询依赖另由TB04和查询正确性测试覆盖。主性能方案的原生输入与GPU完整协议仍保持独立。

M6另执行50k×256 Cells的200组／800次双轴首／中／尾／反向程序定位，逐次核对实际目标bounds、clamp和工作集；这是W2的headless定位子集，不代替原生输入、活动编辑器回窗或完整W1浏览测量。

## 3. 固定操作轨迹

输入先由真实 GPUI owner 接收；采样以实际完成的场景、bounds 和状态计数，不把原始 wheel delta 当滚动位移。纯规则探针不需要开窗口，其结果不与原生窗口帧混成一个指标。

| 轨迹 | 内容 | 必查结果 |
| --- | --- | --- |
| W0 首次挂载／空闲 | 分别记录 source 索引、首帧与尺寸收敛；无输入稳定 120 个调度观察点 | 静态表无持续动画／notify；真正 loading 单独记录；观察调度不能自己制造重绘 |
| W1 连续浏览 | 1,000 次确定纵向步进；Cells 再进行 1,000 次横向步进，固定速度／方向序列 | 每次提交覆盖实际视口；相同输入不重复查询；bounds↔key、实际 owner 位移一致 |
| W2 大跳／反向 | 200 组跳至首／中／尾、立即反向并夹紧边界；加入活动格离屏／回窗 | 下一场景无错误 key／非法空窗，额外保留有界，稀疏项去重，锚点残差样本有效 |
| W3 伸缩／布局 | 同一列 1,000 次绝对 pointer 坐标后释放；另测 Escape；宿主宽度在 48／64／80rem 间循环 100 次 | 末次坐标生效，完成至多一次请求、取消零请求；窗口扩大无需再滚一次才补齐 |
| W4 查询／内容 | TB04 每条件冷／热各测；TB05 固定更新批次；立即保存输入和错误校验另列 | 完整结果与 oracle 一致，保留 0／false，source／query／内容失效次数可核对 |
| W5 生命周期 | 100 次换 source／查询、20 次卸载／合法重挂载；两表共享业务来源 | 旧结果不回写，新表／业务订阅正常，旧 source／闭包／资源可释放，无残留捕获 |

操作序列保存在 runner 输入中，不靠人工“差不多拖动”；W1 的调用次数不等于帧样本数。达到边界而没有实际位移的样本单独标记，不用于伪造零滚动成本。卸载后的样本不可再计正常可见帧；样本丢失与 tracker key 消失必须报告。

## 4. 指标、预算与报告

| 层 | 必报指标 | 确定性硬约束 |
| --- | --- | --- |
| 数据 | accessor／格式化、过滤／排序／投影／聚合次数与耗时，完整 key／total／页结果 | 稳定滚动、hover、选择不重跑 query；一次接受不逐字段重跑全管线 |
| 元素 | cell factory、Entity Render、当前／峰值工作集，精确保留项 | Rows 按 Wr×C；Cells 为工作集、冻结与 P 的去重并集，不能扩成两轴保留乘积 |
| 布局与场景 | layout／prepaint／paint 及可用的 CPU 帧区间；可见 bounds、命中 key | 表头正文 summary 同轨；非法 span／尺寸原子拒绝；无样本不能通过 |
| 资源 | 每操作分配次数／字节、仍活的 source／订阅／任务、文本与图片缓存／纹理字节 | 不随浏览历史无限增长；当前 view、合法会话与声明热缓存之外的旧来源在任务结算后可释放 |
| 交互 | 事件次数、焦点、实际 owner、末次 resize 坐标、锚点残差 | 一项动作一次请求、静默同步零请求；取消／拒绝不发布未接受值；残差容差由物理舍入基线固定 |

Wr／Wc 与 overscan 使用 Base 实际配置，runner 导出本次上界和冻结数量；不以“低于 500 格”替代公式。缓存和测量预算来自本次配置并写报告，任何超限必须有具名必要保留项，不能用平均值掩盖峰值。单张图片大小和 Entity 数量都不能代替资源总字节。

报告至少包含硬件、Windows／驱动、构建／依赖身份、窗口物理尺寸／DPI／rem、数据／轨迹版本、warmup、有效／丢弃样本及原因，和 baseline／candidate 两边的原始记录。GPU 时间只有实际采集时才列；没有输入到呈现的专用探针时不把 CPU paint 时间命名为端到端延迟。

## 5. 采样顺序与接受规则

先完成构建和正确性验收，再按 before→after→after→before 的 ABBA 顺序比较，至少 3 个独立区组；不能把一个运行内的成千帧冒充独立重复实验。持续场景每次先按相同轨迹预热 120 个实际提交帧，再收集至少 1,000 个有效提交帧；W0 空闲不强迫生成这些帧，首次挂载／单次查询另统计独立操作样本。

采样期间采用既有编译／用户 Showcase 干扰门禁；发现干扰丢弃本轮并保留日志，不结束用户进程。不在采样中构建、录屏或增加两边不一致的 instrumentation。纯计算基准和原生输入场景分别运行，资源峰值与分配归因另有明确计时边界。

- **正确性门禁先行**：key、事件、提交、焦点、窗口覆盖、资源归属任一失败即拒绝候选；不能以耗时更低抵消错误。
- **确定性预算**：稳定滚动 query 重算为 0；无变化接受不触发额外布局；resize 释放至多 1 次、取消 0 次修改请求；必要保留以外 Entity／任务无历史增长。
- **时序与内存回归**：初始诊断线为相同场景 median／p95、每操作分配及稳定资源保留恶化超过 5%。M1 先测设备噪声并冻结正式阈值；自然波动已超过诊断线时延长独立采样或报告“不确定”，不根据候选结果临时放宽阈值。
- **吸收优化**：目标指标的收益必须超过 baseline 的实测波动，且正确性、长尾和资源无未解释回归；只减少 factory／命中次数不算帧收益。结果互有代价时记录产品场景和明确取舍，不自动合入。
- **样本限制**：median／p95 使用一致分位定义并写入报告；不足 1,000 个有效帧时不将该次 p99 用作接受证据，单次操作则报告独立样本分布。零样本、缺失 baseline 或版本不一致为失败／未验证。

这些是待冻结的实验规则，不是已达成的性能指标，也不承诺固定 FPS。M1 输出 TB01／W0–W2 的首份可信基线与适用门禁；M2–M5 按能力新增 fixture。只有真实优化进入比较，纯文档修订不运行整套性能实验。
