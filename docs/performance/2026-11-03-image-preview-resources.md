# ImagePreview 图片准备与大图边界（2026-11-03）

测试环境：Windows，Intel Core i5-13600KF，Rust Release。命令：

```powershell
cargo run -p yue-component --example image_preview_resources --release --locked
```

每个样本运行3次，报告中位数；输入是借用的连续BGRA8、Alpha=128。计时包含校验、必要缩图及RenderImage创建，不包含生成源数据、文件I/O、编码／解码、GPU上传或显示。源数据只保留一份；代理准备只分配目标缓冲。日志：`target/image-preview-resource-probe.log`。

| 样本 | 原始尺寸 | 实际纹理 | 源栅格字节 | 预览栅格字节 | 准备中位数 |
| --- | --- | --- | ---: | ---: | ---: |
| 4K | 3840×2160 | 3840×2160 | 33,177,600 | 33,177,600 | 4.147ms |
| 8K | 7680×4320 | 5461×3072 | 132,710,400 | 67,104,768 | 412.233ms |
| 长图 | 1024×32768 | 256×8192 | 134,217,728 | 8,388,608 | 95.581ms |
| 极细长图 | 1×32768 | 1×8192 | 131,072 | 32,768 | 0.200ms |

默认64MiB／8192双预算对所有样本成立。相同资源用于后续缩放／拖动，不重复CPU缩图；这些时间不是每帧开销。原始像素保持不变，可继续复制／导出。

## 本次决策

1. 保留普通图片完整分辨率；修正保存面板固定2048结果纹理，不再无条件牺牲质量检查细节。
2. 超预算明确使用代理，100%按原始尺寸计算但不声称恢复细节；代理禁止原图像素网格。
3. 8K全细节可由有足够总预算的宿主选择128MiB栅格；超长单边仍受8192预览边界约束。
4. 当前不增加分块调度／缓存引擎。上述测试只证明有界静态准备能工作，不能证明超长图原始倍率检查已支持。若产品要求超长图原始细节或8K首次后台准备小于现有约412ms，再设计低清首帧＋按需原分辨率区域／tiles，并测量上传、显存和交互帧率。
5. 不新增完整ICC／HDR管线。当前显式报告未转换色彩元数据；专业色准场景需另立输入、显示器与输出三段可验证合同。

栅格字节不是进程峰值或实际显存；GPUI atlas最小尺寸、GPU副本、解码器、宿主原图及前后版本均在此测量之外。

## 验证边界

CPU回归覆盖缓冲区、通道、透明度、面积采样染边、EXIF、ICC标记、格式和预算；四档DPI无头测试覆盖真实组件几何、完整UV、资源升级、采样选择与网格；Windows WARP读取生产着色器结果，覆盖1:1像素、裁切、atlas边缘隔离及Alpha。

CPU与GPU透明边缘测试均先复现隐藏RGB污染，再验证Alpha加权面积／双线性采样修复。core快照测试另检查直接上传的生命周期：冻结快照持有时保持共享资源，最后持有者释放后在后续draw回收；20次连续替换不能积累旧atlas项。这些验证不测量实际VRAM峰值。

本轮实窗工具返回`Computer Use native pipe is unavailable ... (os error 2)`，没有取得窗口截图、物理显示器DPI切换、Narrator或实际显卡帧率证据。WARP和无头验证不代替实机验收。
